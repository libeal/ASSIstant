# 执行权限边界声明（受管生产安装）

本文档定义受管安装的身份、数据目录、执行通道和特权 helper 边界。配套实现包括 `linux-agent-web`、`linux-agent-runner`、`linux-agent-mcp-stdio`、`linux-agent-observer-helper`、`linux-agent-host-ops` 和 `linux-agent-policy-writer` 的 service/socket unit。

## 身份与授权模型

- Web 进程以专用非 root 用户运行，默认 `linux-agent`。它读取配置、写 Web 状态和用户 Skill staging，但不能直接写策略 overlay 或主机文件。
- 普通执行进程以另一个专用非 root 用户运行，默认 `linux-agent-runner`。Runner 用户不得与 Web 用户相同、不得使用 Web 主组，也不得加入 Web 服务组。
- STDIO MCP server 由 `linux-agent-mcp-stdio` 的 systemd `DynamicUser` 身份启动；该服务隐藏整个持久数据目录，不与读取 HTTP MCP 凭据的 Runner 共用 UID。
- observer、host-ops 和 policy-writer 是彼此独立的窄权限 helper。它们以 root 或最小 capability 运行，但不接受任意命令、shell、路径或 argv。
- 浏览器只向受管 Web 发送 Bearer Token。Web 认证通过后才可调用 helper；Bearer Token、Provider API key 和 sudo 密码都不会传给 Runner/helper。
- 受管 Web 不收集 sudo 密码。旧 `/api/policies/sudo-check` 只作无密码协议兼容；observer bootstrap 的 `password` 字段在受管执行中被忽略且不记录。

源码运行、临时 Remote 和明确 `--no-systemd` 的 release 布局没有 Runner socket 时，普通 Terminal/Skill/MCP/remote script 可使用同 UID 路径，并在 health、UI 和审计中标记 `degraded_same_uid`。经审批且结构化参数通过已安装内置包 adapter 校验的 `host_helper` 操作也可在当前身份下执行；策略和 command guard 直接写当前用户可写的配置/overlay。observer 优先使用 helper，否则 root 直接访问 auditd，非 root 使用已有 sudo 授权；仅 loopback Web 可把一次性密码送入本机 `sudo -S` 标准输入，密码不进入 argv、环境、配置、审计或备份。非 loopback Web 拒绝交互式密码。受管安装缺 Runner/helper 时仍拒绝对应操作，不进行兼容回退。

## 执行通道

| 通道 | 受管执行位置 | 权限与密钥边界 |
| --- | --- | --- |
| Terminal | Runner：`bash -lc` | 独立 Runner UID；白名单环境；看不到配置、Web Token、API key 和特权 socket |
| 普通 Skill | Runner：`bash <script> <json>` | 仅已校验 `SKILL.md + linux-agent.json` 契约中的 `execution.class=runner` tool；成功要求退出码 0、合法 JSON 且 `ok` 严格为 `true` |
| MCP | Runner 调用 adapter；STDIO server 由 DynamicUser relay 启动 | 显式环境白名单；MCP manifest 不能覆盖 Agent 密钥；STDIO server 看不到 Runner 持有的 HTTP credential profile |
| Remote script | Runner 审阅后执行本地副本 | HTTPS 固定解析 IP、逐跳校验、大小/哈希限制；禁止流式管道执行 |
| 主机与 systemd 变更 | host-ops helper | 只接受已安装签名包声明的 capability 和受信 adapter 生成的结构化参数；systemd unit 还必须进入 root-only allowlist，工具使用绝对路径 |
| 策略/command guard | policy-writer helper | 只接受 `policy.write`、`command_guard.set`；目标限于当前 release 登记策略或固定配置字段 |
| auditd observer | observer helper | 只接受固定 audit 状态、规则和查询操作；syscall/用户范围受白名单限制 |
| AI Provider | Web/CLI 编排路径 | API key 只进入 Provider 客户端，不进入 Runner/helper 或执行审计 |

风险等级只决定审批，不决定操作系统身份。高风险普通命令仍进入 Runner；只有已安装并通过统一包解析器校验的内置 Skill tool 可以请求 `host_helper` 或 `credential_helper`。

## Skill 信任与 overlay

每个 Skill 唯一必需文件是带标准 YAML frontmatter 的 `SKILL.md`，可选 `scripts/`、`references/`、`assets/` 和项目扩展 `linux-agent.json`。无扩展的 instruction-only Skill 可安装和披露，但不暴露可执行 tool。扩展中的每个 tool 声明风险、审批域、通用执行类、capability、dispatch、运行时输入和 guard；合法执行类为 `runner`、`host_helper`、`credential_helper`。

- Managed 内置 Skill 位于 release 之外的 `/opt/linux-agent/skills/`；Remote 内置包按签名 release manifest 懒加载。项目级 `INDEX.md` 永久保留内置名称并提供发现元数据。
- 用户 Skill 写入 `/opt/linux-agent/data/skills/`；含 tool 时只允许 `runner`、空 capability、`skill_readonly` 审批域，且不得声明 privileged/Web component。
- 用户 Skill 不得与内置 Skill 重名，也不能通过 `linux-agent.json` 请求 helper capability、Web 路由或自动审批特权。
- 遗留 `manifest.json` 包返回 `legacy_format_unsupported` 并禁用；不存在自动转换或用户级 INDEX。
- 提交使用同目录 staging、完整校验、文件/目录 fsync 和原子 rename；失败保留旧版本。

## 持久数据权限

release 目录为 `root:root` 且只读。安装器建立以下持久布局：

| 路径 | 主要属主/访问者 | 用途 |
| --- | --- | --- |
| `data/config/` | Web 用户；目录 `0700`、配置 `0600` | 配置和固定敏感值；Runner 不可读 |
| `data/logs/`, `data/tmp/` | Web 用户；目录 `0700` | 审计、Job、Web 临时状态 |
| `data/skills/` | Web 用户 + Runner 组；目录 `2750`、文件 `0640` | Web 可原子提交，Runner 只读 |
| `data/runner-tmp/` | Web 用户 + Runner 组；目录 `2750` | Web/Runner 交换经校验的执行 staging；每个调用的 `.mcp-output` 仅允许 Web 列目录、Runner 创建 continuation |
| `data/policies/` | `root:<web-group>`；目录 `0750`、文件 `0640` | policy-writer 写，Web 只读 |
| `data/migration-reports/` | `root:<web-group>`，Web 只读 | 升级迁移和 orphan 报告 |
| `data/migration-conflicts/` | `root:root`、`0700` | 冲突内容隔离，不自动启用 |
| `data/.runtime.lock` | Web 用户:Runner 组、`0640` | Web 可取共享锁，Runner 仅可读/共享锁，root 安装/restore 取独占锁 |

当前 release 提供策略名称和默认值，`data/policies/` 中同名文件是有效 overlay。升级只增加新默认策略，不覆盖已有用户修改；已删除策略作为 orphan 忽略并报告。

## 敏感编辑开关

`web.sensitive_edits_enabled` 是配置中心中的敏感只读项，只能由本机管理员直接编辑 `data/config/config.json`。字段缺失和显式 `true` 都表示开启；非法类型按关闭处理。

- 开启：允许 Web 提交/安装用户 Skill、保存策略和切换 command guard。
- 关闭：仍允许 Skill plan/review、策略读取、草稿、diff 和 validate，但所有最终写入统一返回 HTTP 403 `sensitive_edits_disabled`。
- `/api/config/update` 尝试修改该字段统一返回 HTTP 403 `readonly_config_field`。
- Web、Bash 提交边界和 policy-writer helper 都在最终 rename/写入前重新读取开关，避免仅靠页面禁用或长请求竞态绕过。

## Unix socket 与 helper 校验

所有 socket 使用版本化协议 `1.2.0`、请求大小限制和结构化响应。Runner `execute` 使用带 request-id 和单调序号的 NDJSON 流帧，其他 helper 保持单 JSON 帧。helper 通过 `SO_PEERCRED` 核对调用 UID，并校验操作枚举、参数 schema、计划摘要和目标白名单。

- `runner.sock`：socket mode `0600`，仅 Web 用户可连接，Runner 服务接收；Runner unit 显式隐藏配置、日志和三个特权 socket。
- `mcp-stdio.sock`：socket mode `0660`，仅 Runner 组可连接；服务通过 `SO_PEERCRED` 核对 Runner UID，再以不可访问 `data/` 的 `DynamicUser` 启动 server。server 不继承已连接 socket。
- `observer.sock`、`host-ops.sock`、`policy-writer.sock`：仅 Web 服务用户/组可连接；Runner 用户组与 Web 组隔离。
- 受管模式 socket/helper 缺失或拒绝时 fail-closed。helper 绝不通过 `sudo`、shell 命令字符串或调用方提供的可执行路径兜底。

systemd unit 同时施加 `NoNewPrivileges`、`ProtectSystem=strict`、`ProtectHome`、`PrivateTmp`、system call filter、address family 限制和 cgroup 上限。Runner 与 MCP stdio relay 均配置 `CPUQuota=200%`、`MemoryMax=1G`、`TasksMax=256`；Web 出站由安装器生成的 Provider CIDR drop-in 管理。

## 安装、升级与回滚

安装器在切换 `current` 前校验 schema v2 release、全部 unit/socket、数据权限、Runner 隔离和 helper health。首次安装默认安装签名目录中的全部内置 Skill；升级只更新当前已安装集合，不会重新安装管理员明确卸载的包。旧 `manifest.json` Skill 不会被导入或转换，必须先在上一主版本完成迁移。

迁移前会快照配置、Skill、策略、持久目录和 systemd 状态。同名内置 Skill 冲突报告记录来源/目标版本、相对隔离路径和目录 SHA-256；rollback 使用当前新版 migrator 校验 provenance。目标旧 release 已无同名内置包、目标为空且 digest 匹配时原子恢复，否则 fail-closed 并由安装事务恢复整个切换前状态。

所有 Web 同步请求、后台 Job、CLI/REPL turn、Runner 和 helper 操作在完整业务生命周期持 runtime 共享锁；backup 同样持共享锁。Skill 安装、卸载、Remote 物化、Edit 提交和 restore 在最终提交阶段取得独占锁；Web 生命周期请求会先暂停本请求的共享 barrier，提交完成后重新取得共享锁。restore 锁外验证归档，共享锁下准备并记录指纹，再非阻塞获取独占锁复验；活动读者导致 `restore_busy`，并发修改导致 `restore_conflict`。独占区内按 Skill、policy、config、audit 顺序提交，失败恢复全部旧域；root 新建的审计 log/rotation/lock 只继承已验证日志目录的 owner/group，mode 保持 `0600`。
